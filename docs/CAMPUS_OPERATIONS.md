## 4. 사례 공개 동의 절차 (approvedForCampus)

**공개된 고객 프로필**과 **Campus 판매 페이지 사례 사용 동의**는 별개다.
프로필이 이미 공개되어 있어도 판매 페이지 사례로 쓰려면 별도 동의를 받는다.

1. 후보는 `src/data/campus.ts`의 `cases`에 `approvedForCampus: false`로 둔다.
2. 본인에게 "Campus 판매 페이지에 사례로 노출해도 되는지" 명시적으로 확인한다.
3. 동의를 받은 경우에만 해당 항목을 `approvedForCampus: true`로 바꾼다.
4. 검수: `CAMPUS_REVIEW=1 npm run build` 로 후보 포함 페이지를 확인한다
   (배너 "내부 검수 · 배포 금지"). 프로덕션 빌드(`npm run build`)에는
   미동의 사례가 **HTML에 아예 포함되지 않는다.**
5. 사례 카드에는 이메일·전화·주소·생년월일을 절대 넣지 않는다. 이름·직무·한 줄
   설명·본인이 공개한 링크까지만.

현재 상태: 동의 0건 → 프로덕션에서 사례 섹션과 그 내비게이션이 렌더링되지
않는다. 서바울은 고객 프로필로 유지하되 Campus 대표 사례 후보에서는 제외한다.

## 6. Interview Portfolio 업그레이드 기준

얼리버드 고객이 199,000원 상품으로 올라가는 것이 맞는 경우:
- 보여줄 대표 프로젝트가 1~2개 뚜렷하고, 문제→행동→결과가 설명 가능
- 근거 자료(기획서·보고서·이미지·영상)가 실제로 존재
- 면접에서 프로젝트를 "증명"해야 하는 단계의 지원자

판매 문구 원칙: 현재 정적 빌드 구조에서 **실제로 구현·제공할 수 없는 기능은
약속하지 않는다.** 아래는 기술 검토 후에만 함께 논의(보장 아님):
지원 직무별 첫 화면 2종 / 비밀번호 보호 프로젝트 / 발표형 면접 모드.

## 7. 후기·초기 피드백 정책 (유입 채널별)

공개 페이지에는 다음 취지만 표시한다(결과물 전달의 **조건이 아니다**):

> 첫 10명 초기 고객에게는 완성 후 5분 내외의 솔직한 사용 피드백을 부탁드립니다.
> 좋은 평가나 특정 별점을 요구하지 않습니다.

채널별 요청 기준:
- **에브리타임·지인·자체 채널 고객** → 자체 피드백 설문 사용
- **크몽에서 처음 거래한 고객** → 크몽 내 실제 거래 완료 후에만 크몽 후기 요청 가능
- **숨고에서 처음 거래한 고객** → 숨고 내 실제 거래 절차에 따른 후기만 요청
- 외부 고객을 숨고로 데려가 리뷰를 만들지 않는다.
- 동일 고객에게 크몽·숨고 양쪽 리뷰를 요구하지 않는다.
- 긍정적 후기나 5점을 요구하지 않는다.
- 공개 사례 활용은 §4의 별도 동의를 따른다.

## 8. 신청 접수 / 배포 상태 (분리)

두 상태를 분리해 본다.

| 상태 | 현재 |
| --- | --- |
| Campus Preview 페이지 준비 | 준비됨 (`/campus/` 렌더링·빌드 가능, 검수 가능) |
| 실제 온라인 신청 접수 준비 | **아직 아님** — 검증된 신청 폼 URL 없음 |

- `campusOffer.applyFormUrl = null` 유지. 추측 URL을 만들지 않는다.
- null인 동안: 신청 버튼은 비활성("온라인 신청 준비 중"), 페이지는
  `noindex, nofollow`.
- 오늘은 에브리타임 쪽지 등 수동 채널로 먼저 문의를 받을 수 있다. 검증된 폼이
  생기면 `applyFormUrl`을 채우는 순간 버튼 활성화 + 색인 허용으로 바뀐다.
- **배포되었다고 해서 "판매 준비 완료"로 보고하지 않는다.**
